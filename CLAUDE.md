# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Kleiderstudio** — a virtual try-on web app: the user uploads two images (`image1` = person, `image2` = garment), they are sent (via the server) to an n8n webhook workflow whose URL is configured server-side only, and the composited result image is shown, compared and stored in a per-user cloud history (Supabase). Users must register (name, e-mail, password, e-mail confirmation) and log in before they can generate. All UI text, error messages and code comments are in **German**; keep it that way.

## Commands

- `npm run dev` — starts the Express server (`server.ts`) via `tsx watch`, with Vite mounted as middleware (single port, default 3000). Changes under `src/` are handled by Vite HMR; the server only restarts for server-side changes.
- `npm run build` — `tsc --noEmit` then `vite build` into `dist/`.
- `npm start` — runs `server.ts --prod`, serving `dist/` statically with SPA fallback.
- `npm run typecheck` — type check only (covers `src`, `server`, `server.ts`, `vite.config.ts`).

There is no test runner or linter configured. Requires Node >= 20.11.

Env vars (see `.env.example`): `PORT`, `ALLOW_PRIVATE_WEBHOOKS` (default `false`; set `true` to allow n8n in a LAN/localhost), `WEBHOOK_URL` (the n8n webhook; **required**, lives only in the git-ignored `.env` — never commit it, the repo is public, and never ship it to the browser). `server.ts` loads `.env` via `process.loadEnvFile` if present. Also: `HOST` (default `127.0.0.1`, i.e. not reachable from the LAN), `WEBHOOK_SECRET` (optional, sent to n8n as header `X-Kleiderstudio-Secret` for Header Auth), `RATE_LIMIT_PER_MINUTE` (default 10 per IP) and `MAX_CONCURRENT` (default 3) to limit paid generations. In production a strict CSP is set; result images are only passed through when recognized by magic bytes (no SVG). `SUPABASE_URL` + `SUPABASE_SECRET_KEY` are required for login and the cloud history (without them `/api/history` and the login answer 503, so nobody can generate).

## ⚠️ Supabase-Daten gehören NICHT ins Git-Repo

Das Repo ist öffentlich. Folgendes darf **niemals committet** werden (ist in `.gitignore` eingetragen, trotzdem vor jedem Commit prüfen):
- `.env` / `.env.*` mit `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (und `WEBHOOK_URL`, `WEBHOOK_SECRET`)
- `.mcp.json` (lokale MCP-Konfiguration mit der Supabase-Projekt-Ref)
- lokale Supabase-CLI-Dateien (`supabase/.temp`, `supabase/.branches`, `supabase/.env`)
- Exporte/Dumps von Tabellen oder Bildern aus dem Bucket (enthalten Personenfotos, Namen und E-Mail-Adressen der Nutzer)
- Test-Zugangsdaten (E-Mail/Passwort von Testkonten), Access-/Refresh-Tokens oder kopierte Cookies (`ks_at`, `ks_rt`)

Der Secret Key umgeht RLS und hat Vollzugriff – er gehört nur in `.env` bzw. Vercel Environment Variables, **nie** in `src/`, nie als `VITE_*`, nie in Logs oder Fehlermeldungen. Der Browser spricht nie direkt mit Supabase.

## Architecture

**Request flow:** Browser (logged in, session cookie) → `POST /api/webhook` (multipart: `image1`, `image2`) on the Express proxy → forwards the two images as multipart to `WEBHOOK_URL` → normalizes the response into raw image bytes → saves inputs + result to the Supabase history (if configured) → returns the image with headers `X-Processing-Time-Ms`, `X-Result-Source` (`binary` | `base64` | `url`) and `X-History-Saved` (`1` | `0`).

The browser never calls n8n directly; the proxy exists to avoid CORS and to normalize the many shapes an n8n "Respond to Webhook" node can return.

### Server (`server.ts`, `server/`)
- `server/app.ts` — the Express app with the whole proxy API (`/api/webhook`, `/api/health`, headers, rate limit, error handler). It is shared by `server.ts` (local: adds Vite middleware or static `dist/`, then `listen`) and `api/webhook.ts` (Vercel serverless function, `export default app`). Server-side imports use `.js` extensions so they also resolve as ESM on Vercel.
- **Vercel deployment** (`vercel.json`): static `dist/` + function `api/webhook.ts` (maxDuration 300 s; `/api/history*`, `/api/auth/*` and `/api/billing*` are rewritten to the same function); security headers/CSP for static files are set in `vercel.json`. `WEBHOOK_URL`, `WEBHOOK_SECRET`, `SUPABASE_URL` and `SUPABASE_SECRET_KEY` must be set as Vercel Environment Variables (never as `VITE_*`, that would ship them to the browser). Vercel limits request/response bodies to ~4.5 MB, so `prepareUpload` downscales uploads to max 2048 px.
- `server/app.ts` details — Express 5, multer in-memory upload (25 MB/file, only fields `image1`/`image2`), 240 s upstream timeout (undici agent timeouts 245 s), client-abort propagation via `AbortSignal.any`. Errors are thrown as `ProxyError` and serialized by the final error handler into `ProxyErrorBody` (`error`, `upstreamStatus`, `upstreamContentType`, `upstreamBody`, `hint`). `hintForStatus` and the JSON-without-image branch produce German troubleshooting hints for common n8n misconfigurations (inactive workflow, wrong path, webhook responding immediately).
- `server/imageResponse.ts` — magic-byte sniffing (`sniffImageMime`) and `findImageInJson`, which walks JSON responses looking for inline data-URI/base64 images first, then image URLs (scored by file extension and key name).
- `server/auth.ts` — login via Supabase Auth, proxied by the server (the browser never talks to Supabase and never sees tokens). Routes under `/api/auth`: `POST /register` (`name`, `email`, `password` ≥ 8; `signUp` with `user_metadata.name` and `emailRedirectTo = <origin>/?bestaetigt=1`; answers neutrally `{needsConfirmation}` so registered addresses can't be probed), `POST /login` (sets cookies, returns `{user}`), `POST /logout`, `GET /me` (`{user}` or `{user:null}`), `POST /forgot` (`email`; `resetPasswordForEmail` with `redirectTo = <origin>/`, always answers neutrally `{sent:true}`), `POST /reset` (`accessToken`, `password`; the browser takes the token once from the `#access_token=…&type=recovery` fragment of the mail link; the server accepts only tokens whose JWT `amr` is an e-mail-link method — not `password` —, sets the password via `admin.updateUserById`, signs out all sessions globally and logs in fresh). Session lives in httpOnly cookies `ks_at` (access token) and `ks_rt` (refresh token, 30 days), `SameSite=Lax`, `Path=/api`, `Secure` in prod. `requireUser` verifies `ks_at` with `auth.getUser`, refreshes via `ks_rt` when expired, and puts `{id,email,name}` into `res.locals.user` (use `currentUser(res)`). A fresh Supabase client is created per auth call, because a client that ran `signInWithPassword` would keep the user session — never reuse the service client from `history.ts` for that. `sameOriginGuard` rejects non-GET `/api` requests with a foreign `Origin` (CSRF). Auth attempts are limited to 5/min/IP; generations are rate-limited per user. Names live in `public.profiles` (`id` → `auth.users`, `name`, `email`), filled by the trigger `on_auth_user_created` → `public.handle_new_user()`; RLS on, no policies. Supabase dashboard settings (not in code): Authentication → URL Configuration (Site URL = the production custom domain, which points to Vercel via a DNS-only CNAME; Redirect URLs = custom domain, the `*.vercel.app` domain and `http://localhost:3000/**`, each with `/**`), „Confirm email“ on; Authentication → SMTP Settings uses custom SMTP via Resend (`smtp.resend.com:465`, sender `noreply@` on the user's own domain, DNS verified in Resend) — the API key lives only in the Supabase dashboard. Mail templates „Confirm sign up“ and „Reset password“ (Authentication → Emails) are German custom texts using `{{ .ConfirmationURL }}`; Authentication → Rate Limits: emails 100/h (Resend free tier = 100/day).
- `server/billing.ts` — credits + Stripe Checkout. Each generation costs 1 credit (`public.profiles.credits`, column default 3 = free images for new users). `POST /api/webhook` calls `consume_credit` before forwarding to n8n (402 when empty) and `refund_credit` in `finally` unless the image was delivered/saved; success responses carry `X-Credits-Remaining`. SQL functions `consume_credit`/`refund_credit`/`grant_credits` (execute only for `service_role`); table `public.credit_purchases` (PK = Stripe session id → idempotent grants; RLS on, no policies). Routes under `/api/billing`: `GET /` (`{credits, purchaseEnabled, pack}`; with `?session=cs_…` also `purchaseGranted` for that user's session), `POST /checkout` (inline `price_data`, `metadata.user_id/credits`, success `/?kauf=ok&session={CHECKOUT_SESSION_ID}` — the client polls until `purchaseGranted`, cancel `/?kauf=abbruch`, returns `{url}`), `POST /webhook` (raw body, `stripe.webhooks.constructEvent`; grants on `checkout.session.completed`/`async_payment_succeeded` when `payment_status=paid`; 500 on DB error so Stripe retries). Env: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` (both needed for the buy button), `CREDIT_PACK_SIZE` (25), `CREDIT_PACK_PRICE_CENTS` (999). Client: `src/lib/billing.ts`, `components/CreditsBar.tsx`.
- `server/errors.ts` — `ProxyError` and `ProxyErrorBody`, shared by `app.ts` and `auth.ts`.
- `server/history.ts` — Supabase cloud history (server-only, secret key, `@supabase/supabase-js`). Table `public.generations` (`id` uuid, `user_id` → `auth.users`, `created_at`, `duration_ms`, `source`, and jsonb `image1`/`image2`/`output` = `{path,name,type,size,width,height}`) plus private storage bucket `generations` (files at `<user_id>/<id>/<kind>.<ext>`). RLS is enabled with **no policies** on purpose, so only the server's secret key can access it. Saving happens inside `POST /api/webhook` after a successful generation (failures are only logged); there is deliberately no endpoint that accepts arbitrary uploads into the history. Routes (all behind `requireUser`, every query filtered by `user_id`): `GET /api/history` (own entries, max 100), `GET /api/history/:id/:kind` (streams an image, same-origin so the CSP stays `'self'`; `Vary: Cookie`), `DELETE /api/history/:id`. `POST /api/webhook` also requires login. `HistoryEntryDto` must stay in sync with `HistoryEntry` in `src/types.ts`. `server/imageSize.ts` reads dimensions from image headers (0 if unknown). There is also an extra, currently unused table `public.vitali` (same RLS setup).
- `server/ssrf.ts` — SSRF protection. `parseWebhookUrl` rejects non-http(s), credentials, and obviously local hosts/IPs; `guardedAgent` (undici `Agent` with a custom DNS `lookup`) re-checks every resolved address at connect time, and its custom connector also rejects private IP *literals* (which skip DNS lookup), so redirects and DNS rebinding are covered. **All outbound fetches (webhook and result-image URLs) must use `dispatcher: guardedAgent`.**
- `ProxyErrorBody` (`server/errors.ts`) and `AuthUser` (`server/auth.ts`) are duplicated in `src/types.ts` — keep them in sync.

### Rechtstexte
- Static pages `public/impressum.html`, `agb.html`, `widerruf.html`, `datenschutz.html` (+ `public/legal.css`, no inline styles because of the CSP), served as `/impressum` etc. via `"cleanUrls": true` on Vercel and an explicit route in `server.ts` locally. Personal data of the operator are still placeholders (`<span class="platzhalter">[…]</span>`) — search for `platzhalter` before going live. Texts are a template, not legal advice.
- `components/LegalFooter.tsx` links them on every view. Registration requires the checkbox (`acceptTerms` → server rejects otherwise, stores `terms_accepted_at` in `user_metadata`). Purchases require the § 356 Abs. 5 BGB waiver checkbox in `CreditsBar` (`waiverAccepted` → `POST /api/billing/checkout` rejects otherwise; `metadata.waiver_accepted_at` + `custom_text.submit` on the Stripe session).

### Client (`src/`)
- React 19 + Tailwind CSS v4 (via `@tailwindcss/vite`), `lucide-react` icons. Fonts loaded from Google Fonts in `index.html`.
- `config.ts` — proxy endpoint, upload limit, localStorage keys. The webhook URL must never be put into client code or UI (product decision: it should not be visible on the page).
- `lib/api.ts` — `sendToWebhook` calls the proxy and turns failures into `WebhookError` carrying a `RequestFailure`.
- `lib/image.ts` — creates `ImageAsset`s (type/size validation, dimension measurement) and `prepareUpload`, which converts client-side to WebP/JPEG/original via canvas (falls back to JPEG when the browser can't encode WebP).
- `lib/apiClient.ts` — shared `ApiError`, `request`, `messageOf`, and the 401 hook (`setUnauthorizedHandler`): any 401 from our own server sends the user back to the login screen.
- `lib/auth.ts` — `getCurrentUser`, `register`, `login`, `logout` against `/api/auth`. `components/AuthView.tsx` is the login/registration form (shown instead of studio/history while logged out; handles `?bestaetigt=1` after the confirmation link).
- `lib/history.ts` — client for `/api/history` (list, delete, fetch image blobs for restore/download). The old IndexedDB history (`lib/historyDb.ts`) was removed; old local entries are no longer shown.
- `lib/samples.ts` — rasterizes `public/samples/*.svg` into PNG sample inputs.
- `types.ts` — shared domain types (`RequestState` discriminated union, `View` = `studio` | `history`, `ResultMode`, etc.).

- `App.tsx` — root component: holds all state (`user` — `undefined` while checking, `null` = logged out —, view, slot assets/errors, `RequestState`; upload format is fixed to WebP), sends via `prepareUpload` + `sendToWebhook` (aborting/ignoring stale requests), refreshes the history when the server reports `X-History-Saved: 1`, and wires global shortcuts (Strg+Enter = senden, Strg+V = Bild in aktiven Slot einfügen).
- `components/` — `TopNav`, `UploadSlot`, `ActionBar`, `ResultPanel` (+ `CompareSlider`, `Lightbox`), `HistoryView`, small shared pieces. Styling tokens and `.card`/`.btn-*` classes live in `src/index.css`.
